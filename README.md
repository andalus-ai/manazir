# Manazir

Manazir is the Java-native media foundation for the Andalus ecosystem. It provides reusable media operations and FFmpeg integration so higher-level products such as Dalang do not depend on raw FFmpeg ABI details.

## Current repository state

The repository contains an initial low-level Java Foreign Function & Memory (FFM) binding snapshot generated by `jextract`, under `src/main/java/tech/kayys/manazir/avutil`. The generated snapshot was generated against a macOS SDK and is excluded from portable Maven compilation until reproducible FFmpeg-specific bindings are available.

The handwritten Java 22 Maven build includes exact-time primitives, backend-neutral media-probe contracts, an FFprobe process provider, timestamped single-frame extraction, and bounded audio-segment extraction to PCM WAV.

## Architectural direction

1. **Generated bindings** — low-level, version/platform-sensitive FFM declarations. Treat generated output as an implementation detail.
2. **Native runtime** — library discovery, ABI/platform checks, capability reporting, and native resource lifecycle.
3. **Typed media API** — stable Java contracts for probing, streams, timestamps, extraction, transcoding, progress, cancellation, and diagnostics.
4. **Execution adapters** — FFprobe/FFmpeg process adapters provide metadata probing, single-frame extraction, and audio-to-WAV extraction; a native FFmpeg FFM provider remains gated on reproducible bindings and ABI verification.
5. **Product integrations** — Dalang and other consumers depend on typed Manazir contracts, never generated binding classes.

## Design invariants

- Preserve stream timestamps as integer ticks plus exact rational time bases; keep container clocks separate and preserve missing stream time bases as absent.
- Represent frame rates as exact frames-per-second ratios, not time bases.
- Make native memory ownership and lifetime explicit. Never return a `MemorySegment` whose owning arena has already closed.
- Avoid loading native libraries as an accidental side effect of referencing API types.
- Report native capabilities and library versions explicitly; fail with actionable diagnostics when a required library is missing or incompatible.
- Keep FFmpeg operations bounded, observable, and safe to run concurrently.
- Do not let Dalang-specific concepts (projects, timelines, edit proposals, clipper workflows) leak into Manazir.

## Media provider selection

`MediaProviderRegistry<T>` is an explicit immutable registry. Providers declare supported `MediaCapability` values, availability evidence, priority and diagnostics. Selection is deterministic (priority, then provider ID); an explicitly requested provider is strict unless the caller opts into `ALLOW_FALLBACK`. Unknown availability is never auto-selected. The registry does not discover providers or load native libraries.

`ExecutableAvailabilityCheck` explicitly smoke-tests an executable's `-version` command with a timeout. This proves only that the process can run; it does not prove codec/container support or any media operation. Native providers must use the explicit native load/version/symbol verification path before advertising capabilities.

The registry is now connected to both operation facades:
- `SelectingMediaProbe` routes `MEDIA_PROBE` requests to a registered `MediaProbe`.
- `SelectingFrameExtractor` routes `VIDEO_DECODE` requests to a registered `FrameExtractor`.

The application explicitly builds and supplies each registry, including capability evidence and selection policy. No service silently starts a process, loads native libraries, or substitutes a backend.

## Process adapters

- `FfprobeMediaProbe` probes local-file metadata using an argument vector, timeout, and bounded JSON capture.
- `FfmpegFrameExtractor` extracts one timestamped video frame to a caller-selected PNG/JPEG artifact.
- `FfmpegAudioExtractor` extracts a selected audio stream and requested interval to signed 16-bit PCM WAV. It validates output metadata, enforces time/size limits, and refuses to overwrite an existing destination.

These subprocess adapters are not OS-level sandboxes. Do not expose them to hostile multi-tenant workloads without additional isolation.
