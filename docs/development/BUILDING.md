# Building Manazir

## Requirements

- JDK 22 or newer. The handwritten runtime uses the finalized Foreign Function & Memory API.
- Maven 3.9 or newer.

CI verifies the handwritten Java source and unit tests on Temurin JDK 22 and 25. This is a Java source-compatibility check, not a native FFmpeg deployment matrix.

## Build and test

```bash
mvn --batch-mode --no-transfer-progress clean verify
```

The default build does not require FFmpeg native libraries. Runtime and timestamp contract tests use injected dependencies and deterministic values.

## Generated binding status

The checked-in `tech.kayys.manazir.avutil` snapshot was generated by jextract against a macOS SDK. Its generated declarations include platform C runtime and system-header types (for example, `sys/wait.h`), not a pinned FFmpeg header set. It is therefore not a portable or supported FFmpeg ABI binding.

Maven deliberately excludes this snapshot from compilation. The files remain in the repository as an audit artifact only; handwritten code must not depend on them. Do not remove the compiler exclusion until all of the following are committed:

1. A pinned FFmpeg release/header set.
2. A pinned jextract release and exact generation command.
3. A documented target OS/architecture/ABI matrix.
4. Regenerated FFmpeg-specific bindings isolated from host C runtime declarations.
5. CI that regenerates or verifies the checked-in generated output.

## Native runtime initialization and verification

Native loading is explicit:

```java
var loaded = NativeRuntime.system()
    .initialize(NativeRuntimeConfig.ffmpegDefaults());

var verification = new NativeRuntimeVerifier(new FfmpegNativeLibraryInspector())
    .verify(loaded);
```

The inspector uses Java 22 FFM `SymbolLookup.loaderLookup()` to resolve FFmpeg symbols from libraries already loaded into the process. It queries component version functions and checks selected stable API symbol groups. It must run after `NativeRuntime.initialize`.

A VERIFIED capability means the relevant component API symbols resolved. It does not prove that a particular codec, container, pixel format, hardware device, or media operation works. Those require runtime enumeration or execution probes.

## Opt-in native integration test

On a machine with FFmpeg shared libraries installed:

```bash
mvn -Pnative-integration test
```

This profile enables native access for the test JVM and activates the native integration test. If libavutil is unavailable, the test is skipped by an assumption. The default CI does not claim native ABI compatibility.
